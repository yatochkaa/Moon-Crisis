# Moon Courier Crisis

Небольшая стратегическая игра про доставку грузов на Луне. Игрок выбирает заказ и ровер, оценивает вес, расстояние, расход батареи и риск, запускает доставку и зарабатывает кредиты. Проект создан как основа тестового задания: приоритет — архитектура, безопасность серверного кода, детерминированная игровая логика и тесты, а не визуальный дизайн.

> Интерфейс намеренно минимальный и функциональный. Визуальный дизайн — отдельный следующий этап.

---

## Демонстрационный сценарий

1. Откройте `http://localhost:3000`.
2. В строке состояния видно: день 1 из 7, 500 кредитов из 4000, рейтинг 100 (минимум 60).
3. Выберите заказ «Медикаменты для станции» и ровер `Scout-01` — автоматически появится preview: расход батареи, длительность, риск, награда.
4. Нажмите «Запустить доставку» — сервер пересчитает всё заново, определит результат, начислит награду при успехе и добавит запись в журнал событий.
5. Попробуйте «Реакторный модуль» (80 кг) — запуск заблокирован: превышена грузоподъёмность у всех роверов.
6. Попробуйте «Геологические образцы» (Бассейн Айткена) — запуск заблокирован: не хватает заряда батареи.
7. «Буровая установка» (45 кг) доступна только для `Cargo-02`.
8. Нажмите «Завершить день» — день увеличится, просроченные заказы получат статус `expired`, роверы подзарядятся, рейтинг снизится за просрочки.
9. Кнопка «Сбросить игру» возвращает детерминированное начальное состояние (только для локального запуска, см. «Ограничения»).

```bash

cp .env.example .env
```

`.env` содержит только локальные значения:

```env

```

## Тесты

```bash
pnpm test          # Vitest: unit + интеграционный тест
pnpm typecheck     # tsc --noEmit
pnpm lint          # ESLint
pnpm e2e           # Playwright (нужен ALLOW_GAME_RESET=true)
pnpm audit         # аудит зависимостей
```

Unit-тесты покрывают все критические правила: расход батареи, грузоподъёмность, недостаток заряда, занятый ровер, недоступный заказ, просроченный дедлайн, зависимость риска от зоны, ограничение риска 0–90, неотрицательную батарею, однократное начисление награды, отсутствие награды при неудаче, идемпотентность, просрочку заказов при завершении дня, условия победы и поражения, детерминированность случайного результата.

Интеграционный тест (`tests/integration/startDelivery.test.ts`) запускает реальный application service на in-memory репозиториях с транзакционной границей: проверяет однократное начисление награды, повтор `idempotencyKey` и откат при ошибке внутри транзакции.

## Игровые правила (кратко)

Единицы измерения: расстояние — км, вес — кг, батарея — проценты (0–100), длительность — часы, риск — проценты (0–90), награда — кредиты.

```
baseDistanceCost = distance * location.batteryModifier
cargoCost        = order.weight * 0.25
batteryCost      = ceil((baseDistanceCost + cargoCost) / rover.efficiency)

duration         = ceil(distance / (rover.speed * location.speedModifier))

loadRatio        = order.weight / rover.capacity
risk             = clamp(round(order.baseRisk + location.riskBonus + loadRatio * 10), 0, 90)
```

Доставка невозможна, если: сессия завершена, заказ недоступен, ровер не `idle`, вес больше грузоподъёмности, расход батареи больше текущего заряда, дедлайн прошёл, сущность не найдена или `idempotencyKey` уже использован.

Победа — кредиты достигли цели. Поражение — рейтинг ниже минимума или закончились дни. Подробности: `docs/game-rules.md`.

## API

| Метод | Путь | Тело | Назначение |
| --- | --- | --- | --- |
| GET | `/api/game` | — | состояние сессии, заказы, роверы, локации, последние события |
| POST | `/api/deliveries/preview` | `{orderId, roverId}` | информационный расчёт: `canStart`, `batteryCost`, `duration`, `risk`, `reward`, причины блокировки |
| POST | `/api/deliveries` | `{orderId, roverId, idempotencyKey}` | запуск доставки в транзакции |
| POST | `/api/game/end-day` | — | завершение дня |
| POST | `/api/game/reset` | — | пересоздание тестовой сессии (только локально) |

Единый формат ошибки:

```json
{
  "error": {
    "code": "INSUFFICIENT_BATTERY",
    "message": "Недостаточно заряда для этого маршрута",
    "details": {}
  }
}
```

Stack trace и сообщения Prisma клиенту не возвращаются никогда.

## Безопасность

- Клиент передаёт только `orderId`, `roverId`, `idempotencyKey`; награда, расход батареи, риск, результат, кредиты и статусы считаются на сервере из базы.
- Все входные данные валидируются Zod-схемами (`strict`, лишние поля отклоняются).
- Запуск доставки выполняется в транзакции с повторной загрузкой сессии, заказа, ровера и локации.
- `idempotencyKey` имеет unique-ограничение; повторный запрос возвращает сохранённый результат без второго начисления награды.
- Батарея никогда не уходит ниже 0, риск всегда в диапазоне 0–90.
- Prisma Client изолирован в `src/infrastructure` (`import 'server-only'` + правило ESLint `no-restricted-imports`).
- Security headers настроены в `next.config.ts`.
- Аутентификации нет — это осознанное ограничение, честно описанное в `docs/security.md`.

## Ограничения

- **Проверки выполнены локально 13.08.2026** (Windows, Node 24.18.0, pnpm 10.13.1): `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` проходят успешно; `pnpm audit` нашёл 41 уязвимость в зависимостях (разбор и план обновления — в `docs/security.md`); `pnpm exec playwright test` пока не запускался. `pnpm-lock.yaml` создаётся первым `pnpm install`.
- `POST /api/game/reset` предназначен только для локального тестового проекта и по умолчанию выключен (`ALLOW_GAME_RESET=false`). В реальном продукте такой эндпоинт требовал бы аутентификации и прав.
- Одна игровая сессия с фиксированным id (`session-local`), мультиплеера и пользователей нет.
- SQLite поддерживает лишь один писатель одновременно: при параллельных запусках возможна ошибка блокировки. Поведение и переход на PostgreSQL описаны в `docs/security.md`.
- Enum-значения хранятся как TEXT (ограничение SQLite) и проверяются в domain layer и Zod-схемами.
- Доставка разрешается внутри того же игрового дня: `duration` информационный, ровер сразу возвращается в `idle`.
- CSP содержит `'unsafe-inline'` для стилей, так как Next.js внедряет inline-стили; nonce-подход — задача следующего этапа (`TASKS.md`).
